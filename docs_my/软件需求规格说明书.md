# 1. 引言

## 1.1 编写目的

本文档旨在明确 Ragent AI 平台的功能需求与非功能需求，为后续的系统设计、开发实现及测试验收提供依据。文档重点覆盖 fork 后的功能增强部分，包括混合检索通道、中文分词优化、AIHubMix 模型接入、评估系统、前端管理功能增强等内容。

## 1.2 读者对象

- **课程评审教师**：了解项目整体功能范围和实现程度
- **开发人员**：理解功能需求细节，指导编码实现
- **测试人员**：依据需求规格设计测试用例
- **项目维护者**：作为后续迭代的需求基线

## 1.3 软件项目概述

- **项目名称**：Ragent AI（简称 Ragent）
- **源码来源**：Fork 自 [nageoffer/ragent](https://github.com/nageoffer/ragent)
- **开发单位**：个人（lhkeeper），基于开源项目进行功能增强
- **项目类型**：企业级 Agentic RAG（检索增强生成）平台
- **主要功能**：文档入库→智能问答的完整 RAG 链路，涵盖多路检索、意图识别、模型路由、MCP 工具调用、会话管理等
- **技术栈**：Java 17 + Spring Boot 3.5 + PostgreSQL/pgvector + Redis + RocketMQ + React 18

## 1.4 文档概述

本文档按照标准软件需求规格说明书结构组织：第1章介绍项目背景；第2章描述软件与外部环境的关系及约束；第3章详细描述功能需求，包括用例模型和分析模型；第4章描述性能、界面、交付等非功能需求；第5章提供软件原型说明。

## 1.5 定义

| 术语 | 定义 |
| --- | --- |
| RAG | Retrieval-Augmented Generation，检索增强生成，结合信息检索与大语言模型生成的技术范式 |
| Agentic RAG | 具备自主决策能力的 RAG 系统，能根据意图选择检索策略、调用工具 |
| MCP | Model Context Protocol，模型上下文协议，用于模型与外部工具的标准化交互 |
| RRF | Reciprocal Rank Fusion，倒数排名融合算法，用于合并多个检索通道的结果 |
| zhparser | PostgreSQL 中文分词扩展，支持中文全文检索 |
| Rerank | 重排序，对初步检索结果进行二次精排以提升相关性 |
| 向量检索 | 基于嵌入向量相似度（Cosine等）的语义检索方式 |
| 混合检索 | 融合向量检索与关键词检索（全文检索）的多通道检索策略 |
| SSE | Server-Sent Events，服务端推送事件，用于流式输出 |

# 2. 软件的一般性描述

## 2.1 软件产品与其环境之间的关系

Ragent AI 作为企业级 RAG 平台，与以下外部系统存在交互关系：

- **PostgreSQL 数据库**：存储知识库元数据、文档信息、用户数据、系统配置等。通过 pgvector 扩展支持向量存储与检索；通过 zhparser 扩展支持中文全文检索。
- **Redis**：提供分布式缓存、会话管理、分布式排队限流（ZSET + Pub/Sub）。
- **RocketMQ**：消息队列，用于文档入库等异步任务的处理。
- **Milvus（可选）**：向量数据库，作为 pgvector 的替代向量存储方案。
- **AI 模型服务**：通过 HTTP API 调用外部大语言模型，支持多家供应商：
  - 阿里云百炼（BaiLian）
  - 硅基流动（SiliconFlow）
  - Ollama（本地部署）
  - AIHubMix（新增集成）
- **前端用户**：通过浏览器访问 React SPA 前端，经 Vite 开发代理或 Nginx 反向代理与后端 REST API 通信。
- **MCP 工具服务**：独立进程运行的 MCP Server，提供业务工具能力。

## 2.2 限制与约束

1. **数据库约束**：生产环境必须使用 PostgreSQL 且安装 pgvector 扩展；混合检索依赖 zhparser 中文分词扩展。
2. **JDK 版本**：要求 Java 17 及以上。
3. **模型依赖**：系统功能依赖外部 AI 模型服务的可用性，模型故障时通过熔断和自动切换机制降级。
4. **前端代理**：Vite 开发服务器将 `/api` 代理至 `localhost:8080`，但后端实际运行在 9090 端口，需注意端口配置一致性。
5. **内存限制**：文档入库 Pipeline 处理大文件时需注意 JVM 堆内存配置，上传文件限制为 50MB。
6. **操作系统**：Docker 环境在 Windows 上运行需注意路径挂载和换行符差异。

## 2.3 假设与前提条件

1. 用户具备基本的 Docker 和 Linux 命令行操作能力。
2. 部署环境中 PostgreSQL、Redis 等基础服务已就绪或通过 docker-compose 一键启动。
3. AI 模型服务的 API Key 已提前申请并配置。
4. 用户上传的文档为系统支持的格式（PDF、Markdown、TXT、DOCX 等）。
5. 前端用户使用现代浏览器（Chrome、Edge、Firefox 最新版）。

# 4. 其它软件需求描述

## 4.1 性能要求

| 指标 | 要求 |
| --- | --- |
| 问答响应首包延迟 | 不超过 5 秒（含检索+模型首包） |
| 检索耗时 | 混合检索（含融合）不超过 2 秒 |
| SSE 超时 | 全局超时 300 秒（可配置） |
| 并发问答 | 支持最大 10 个并发请求（Redis ZSET 限流） |
| 文档入库 | 单文件限制 50MB，入库任务异步处理 |
| 数据库连接 | HikariCP 连接池最大 10 连接 |

## 4.2 设计约束

1. **开发语言**：后端 Java 17，前端 TypeScript + React 18
2. **框架**：Spring Boot 3.5.7，不依赖 Spring AI 或 LangChain4j
3. **构建工具**：Maven，Spotless 代码格式化（编译时自动执行）
4. **数据库**：PostgreSQL + pgvector + zhparser；可选 Milvus
5. **缓存/消息**：Redis、RocketMQ
6. **鉴权**：Sa-Token，token 名称为 `Authorization`
7. **API 前缀**：`/api/ragent`
8. **代码质量**：所有模块遵循统一的三级异常体系（Client/Remote/Service），带错误码
9. **安全性**：不允许将密钥写入代码；敏感配置通过环境变量或外部配置文件注入
10. **可扩展性**：检索通道、后处理器、MCP 工具、意图节点均采用接口+自动发现机制，新增组件无需修改核心链路代码

## 4.3 界面要求

1. **技术框架**：React 18 + shadcn/ui 组件库
2. **响应式布局**：管理后台适配桌面端（1920×1080 及以上分辨率为主）
3. **文档预览**：支持 Markdown 渲染预览和 PDF 内嵌预览
4. **Trace 详情**：以树形结构展示问答全链路的各节点信息，支持节点展开/收起
5. **时间显示**：支持绝对时间和相对时间（如"3分钟前"）切换
6. **批量操作**：知识文档列表支持多选批量操作

# 5. 软件原型

## 5.1 混合检索配置原型

系统设置页面提供混合检索相关的可配置参数：

- **启用混合检索**：开关控制
- **融合策略选择**：RRF / 加权求和
- **RRF 常数 k**：默认 60
- **向量通道权重**：0.0 ~ 1.0（仅加权求和模式）
- **关键词通道权重**：0.0 ~ 1.0（仅加权求和模式）
- **启用 Rerank**：开关控制

## 5.2 管理后台原型说明

管理后台包含以下主要页面：

- **知识库列表页**：展示所有知识库，支持 CRUD
- **知识文档页**：展示某知识库下的文档，支持批量操作、文档预览（Markdown/PDF）、分块状态查看、更新人/更新时间显示
- **入库流水线页**：展示入库 Pipeline 节点配置和运行状态
- **任务管理页**：展示入库任务的执行日志和状态
- **系统设置页**：配置检索参数、模型参数、Rerank 开关等
- **Trace 详情页**：树形展示一次问答的完整链路，包含检索结果、意图识别结果、模型调用信息等
- **用户管理页**：管理平台用户

## 5.3 混合检索流程示意

```
用户查询: "Ragent如何配置模型路由？"
    │
    ├──▶ 向量检索 (pgvector/Milvus)
    │    └── 语义匹配 → [结果集A] (Top K₁)
    │
    ├──▶ 关键词检索 (zhparser 分词)
    │    └── 分词: ["Ragent", "配置", "模型", "路由"]
    │    └── 全文检索 (OR语义) → [结果集B] (Top K₂)
    │
    ▼
  RRF 融合排序
    │
    ▼
  去重 → Rerank 重排序 → 最终结果集
```
