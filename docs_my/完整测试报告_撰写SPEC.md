#### 4.2 RRF融合排序（RRFFusionStrategy）—— **必须新增**

| 测试项 | 测试方法 | 预期结果 |
|--------|---------|---------|
| RRF公式正确性 | 单元测试：构造已知排名的两路结果，手动计算RRF分数，对比代码输出 | 与手算一致 |
| k值敏感性 | k=10/30/60/100 四组对比，观察排序稳定性 | k=60时排序最稳定（默认值合理） |
| 极端排名处理 | 一路为空、一路仅1条、两路完全不重叠 | 不崩溃、退化为单路结果 |
| 与加权求和的对比 | 同一批数据走RRF和WeightedSum各一次，人工评判排序质量 | RRF对长尾结果更友好 |

#### 4.3 加权求和融合（WeightedSumFusionStrategy）—— **必须新增**

| 测试项 | 测试方法 | 预期结果 |
|--------|---------|---------|
| 权重配比测试 | vector:keyword = 0.9:0.1 / 0.7:0.3 / 0.5:0.5 三组，对比排序 | 0.7:0.3 平衡语义与字面 |
| 权重大小边界 | weight=0.0（纯关键词）/ weight=1.0（纯向量）| 退化为单路 |
| 分数归一化 | 两路分数量纲不同时，归一化后的融合效果 | 归一化后更合理 |

#### 4.4 去重后处理（DeduplicationPostProcessor）—— **必须新增**

| 测试项 | 测试方法 | 预期结果 |
|--------|---------|---------|
| 完全重复去重 | 两路返回相同chunk_id | 保留一条 |
| 近似重复处理 | 相邻chunk（overlap部分）| 按策略处理 |
| 去重后数量 | 统计去重前后chunk数量变化 | 去重率合理（不丢有效信息） |
